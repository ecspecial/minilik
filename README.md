# MVP: ИИ-конвейер изделия (фото → анализ → агенты → юнит-экономика)

Стек: **NestJS** (API, JWT, интеграция с ИИ), **React + Vite** (интерфейс на русском).

## Требования

- Node.js 20+
- Ключ `OPENAI_API_KEY` в `.env` бэкенда

## Запуск

### 1. Бэкенд

```bash
cd backend
copy .env.example .env
# Укажите OPENAI_API_KEY; OPENAI_MODEL по умолчанию gpt-5.4 (см. .env.example)
npm run start:dev
```

API: `http://localhost:3000/api`

Вход: задайте в `.env` бэкенда две пары **`AUTH_LOGIN_USER_1` / `AUTH_LOGIN_PASS_1`** и **`AUTH_LOGIN_USER_2` / `AUTH_LOGIN_PASS_2`** (значений по умолчанию нет). В Docker те же переменные обязательны в корневом `.env` для `docker compose`.

### 2. Фронтенд

```bash
cd frontend
npm run dev
```

Откройте `http://localhost:5173`. Запросы к `/api` проксируются на бэкенд.

## Поток

1. Вход → создаётся сессия.
2. Загрузка **до 3** изображений.
3. **Анализ изделия по фото**: тип изделия строго из списка `backend/src/constants/product-types.ts`; остальные поля карточки — по результатам распознавания.
4. Пользователь **подтверждает или отклоняет** анализ. Цепочка агентов запускается **только после подтверждения**.
5. Параллельно/последовательно: конструктор, технолог, закупщик; затем **финансист** (расчёт по заглушкам для WB / Ozon / сайт × пессимист / база / оптимист), маркетолог, фото-студия; опционально **генерация изображения** (модель задаётся в `.env`, см. `.env.example`).

Комиссии и логистика — **не боевые**, см. `backend/src/constants/economy-stubs.ts`. Сверка с полным Excel не входит в MVP.
